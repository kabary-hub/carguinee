1. Vue d'ensemble du projet

CarGuinée est une plateforme web de mobilité dédiée au marché guinéen (Conakry). Elle permet aux utilisateurs de :

  • Rechercher des véhicules disponibles à la location (avec chauffeur) ou à la vente
  • Réserver un véhicule pour une période donnée
  • Gérer ses annonces en tant que propriétaire
  • Administrer la plateforme (validation, gestion des comptes)
三位制 de rôles : La plateforme distingue trois types d'utilisateurs — Client, Propriétaire et Administrateur — chacun disposant d'un espace dédié.

2. Architecture technique

L'application suit une architecture client-serveur séparée :

🖥️ Backend (API REST)

  • Serveur Express.js (TypeScript)
  • Base de données PostgreSQL via Prisma ORM
  • Authentification JWT
  • Gestion des fichiers (photos multer)
  • Port : 3000

🌐 Frontend (SPA)

  • React 18 + TypeScript
  • React Router v6 (navigation)
  • Tailwind CSS (design responsive)
  • Vite (build tool)
  • Port : 5173

8. Système d'authentification

8.1 Flux de connexion

  1. L'utilisateur saisit son numéro de téléphone et son mot de passe
  2. Le normalizeGuineaPhone formate le numéro au format international +224XXXXXXXXX
  3. Le mot de passe est comparé avec le hash bcrypt en base
  4. Un JWT est généré (durée 24h) contenant : sub (userId), phone, role
  5. Le token est stocké en sessionStorage (clé : carguinee_access_token)
  6. Le profil utilisateur est envoyé au frontend

8.2 Middleware d'authentification

  • requireAuth : Vérifie la présence et la validité du JWT dans le header Authorization
  • requireRoles(...roles) : Vérifie que le rôle de l'utilisateur fait partie des rôles autorisés

8.3 Gestion du profil

  • PATCH /api/auth/me : Permet de modifier prénom, nom, email et téléphone
  • Vérification de l'unicité du téléphone et de l'email
  • Le frontend recharge la page après modification pour synchroniser le contexte

9. Gestion des véhicules

9.1 Cycle de vie d'un véhicule

BROUILLON → EN_ATTENTE_VALIDATION → PUBLIEE

ou

EN_ATTENTE_VALIDATION → REJETEE → BROUILLON
  1. Création : Le propriétaire crée un véhicule → statut BROUILLON
  2. Ajout de photos : 1 à 8 photos (JPG/PNG/WebP, max 2 Mo chacune)
  3. Soumission : Le propriétaire soumet → EN_ATTENTE_VALIDATION (vérifie qu'au moins 1 photo existe)
  4. Validation : L'admin approuve (→ PUBLIEE) ou rejette avec motif (→ REJETEE)
  5. Modification : Toute modification d'un véhicule publié le repasse en EN_ATTENTE_VALIDATION
  6. Archivage : Un propriétaire peut archiver son véhicule → ARCHIVEE
  7. Suppression : Un propriétaire ne peut supprimer que ses BROUILLON ou REJETEE (pas de réservation active)

10. Système de réservation

10.1 Cycle de vie d'une réservation

StatutDescriptionQui change ?
EN_ATTENTEDemande créée par le clientClient (création)
CONFIRMEEAcceptée par le propriétairePropriétaire
EN_COURSLocation en coursPropriétaire/Admin
TERMINEELocation terminéePropriétaire/Admin
ANNULEEAnnulée par le clientClient
REJETEERefusée par le propriétairePropriétaire

10.2 Calcul du montant

  • Montant total = Nombre de jours × Tarif journalier
  • Caution = Montant défini par le propriétaire (optionnel)
  • Vérification de conflit : impossible de réserver sur une période chevauchant une réservation EN_ATTENTE, CONFIRMEE ou EN_COURS

10.3 Interface côté client

  • Cartes cliquables avec aperçu des infos
  • Clic sur une carte → ouvre la modale de détails de la réservation
  • Bouton « Annuler » avec modale de confirmation + toast

10.4 Interface côté propriétaire

  • Tableau des réservations reçues avec pagination (10 par page)
  • Boutons « Confirmer » / « Refuser » avec modale de confirmation
  • Accès rapide depuis le lien « Voir toutes les réservations »

14. Guide d'installation

14.1 Prérequis

  • Node.js ≥ 18
  • PostgreSQL ≥ 14
  • npm ou npx

14.2 Configuration Backend

# 1. Installer les dépendances
cd backend && npm install

# 2. Configurer la base de données
cp .env.example .env
# Éditer .env avec vos identifiants PostgreSQL

# 3. Appliquer le schéma
npx prisma migrate dev

# 4. Charger les données démo
npx prisma db seed

# 5. Mettre à jour les comptes (nouveaux identifiants)
npx tsx prisma/update-accounts.ts

# 6. Démarrer le serveur
npm run dev

14.3 Configuration Frontend

# 1. Installer les dépendances
cd frontend && npm install

# 2. Démarrer le serveur de développement
npm run dev
